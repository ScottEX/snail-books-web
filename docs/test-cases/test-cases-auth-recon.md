# 登录注册忘记密码 / 对账 / 对账记录 — 测试用例

> 涉及文件：`LoginScreen.tsx`、`ExpenseScreen.tsx`、`ReconHistoryScreen.tsx`、`i18n.ts`、`api/client.ts`、后端 `app.py`

---

# Part A — 登录 / 注册 / 忘记密码

## A1. 页面加载

| # | 测试项 | 预期 |
|---|--------|------|
| A1.1 | 页面加载 | 显示品牌 logo、副标题、语言切换按钮（简/繁/EN）、登录/注册 Tab、玻璃态卡片 |
| A1.2 | 已有登录态 | localStorage 有 `user` 时自动调用 onLogin 跳过登录页 |
| A1.3 | 已保存用户名 | localStorage 有 `saved_login` 时自动填入用户名字段 |

## A2. 登录

| # | 测试项 | 预期 |
|---|--------|------|
| A2.1 | 正常登录 | 输入正确账号密码 → 保存 token/user/user_id/saved_login 到 localStorage → onLogin |
| A2.2 | 空字段 | 任一字段为空 → 提示 `errEmptyFields`，输入框抖动 |
| A2.3 | 错误密码 | 输入错误密码 → 显示后端返回的错误消息，输入框抖动 |
| A2.4 | 未验证用户 | 登录返回 need_verify → 自动跳到验证步骤，email 预设 |
| A2.5 | 回车提交 | 密码输入框按回车触发登录 |
| A2.6 | 密码显隐切换 | 点击眼睛图标切换 secureTextEntry |

## A3. 注册

| # | 测试项 | 预期 |
|---|--------|------|
| A3.1 | 正常注册 | 输入用户名/邮箱/密码/确认密码 → 调用 register API → 跳到验证步骤 |
| A3.2 | 空字段 | 任一为空 → 提示 `errEmptyFields` |
| A3.3 | 密码不一致 | password !== password2 → 提示 `errPwMismatch` |
| A3.4 | 密码太短 (<6) | 提示 `errPwTooShort` |
| A3.5 | 密码无字母 | 提示 `errPwNeedLetter` |
| A3.6 | 密码无数字 | 提示 `errPwNeedNumber` |
| A3.7 | 用户名已存在 | 后端返回错误 → 显示消息 |
| A3.8 | Tab 切换 | 登录 → 注册切换，用户名被清空；注册 → 登录，恢复已保存的用户名 |
| A3.9 | 回车提交 | 确认密码输入框按回车触发注册 |

## A4. 验证邮箱

| # | 测试项 | 预期 |
|---|--------|------|
| A4.1 | 输入验证码 | 6 位数字键盘输入，按回车提交 |
| A4.2 | 正确验证 | API 返回 ok → 提示 `msgVerifyOk` → 跳回登录 |
| A4.3 | 错误验证码 | 显示错误消息，输入框抖动 |
| A4.4 | 重发验证码 | 点击发送 → 30 秒倒计时，期间按钮禁用 |
| A4.5 | 倒计时结束 | 恢复"重新发送"，可再次点击 |
| A4.6 | 返回登录 | 点击 `backToLogin` → 回到登录步骤 |

## A5. 忘记密码

| # | 测试项 | 预期 |
|---|--------|------|
| A5.1 | 输入邮箱 → 发送 | 调用 forgotPassword API → 跳到重置步骤 |
| A5.2 | 空邮箱 | 提示 `errEmptyFields` |
| A5.3 | 不存在的邮箱 | API 返回 ok（防枚举），跳到重置步骤（但后端未实际发码） |

## A6. 重置密码

| # | 测试项 | 预期 |
|---|--------|------|
| A6.1 | 输入验证码 + 新密码 | 调用 resetPassword API |
| A6.2 | 成功重置 | 显示 `msgResetOk` → 跳回登录 |
| A6.3 | 空验证码或空密码 | 提示 `errEmptyFields` |
| A6.4 | 密码强度不足 | 与注册相同校验 |
| A6.5 | 没有确认密码字段 | **确认无二次密码输入** |

## A7. 多语言

| # | 测试项 | 预期 |
|---|--------|------|
| A7.1 | 简体中文 | 所有文字简体 |
| A7.2 | 繁體中文 | 所有文字繁体 |
| A7.3 | English | 所有文字英文 |

# Part B — 对账页面 (ExpenseScreen)

## B1. 卡片式 Tab 栏

| # | 测试项 | 预期 |

## B2. 对账表单 (Tab 0)

| # | 测试项 | 预期 |
|---|--------|------|
| B2.1 | 日期选择 | 默认昨天日期；点击日期 → 弹出原生日期选择器 |
| B2.2 | 切换历史日期 | 选择已对账过的日期 → 自动从后端加载该日对账数据 |
| B2.3 | 选择未对账日期 | 所有字段清空 |
| B2.4 | 卡余额输入 | 只能输入数字和小数点 |
| B2.5 | 现金余额输入 | 同上 |
| B2.6 | 渠道金额输入 | 堂食/美团/闪购/京东/团购，各自独立输入 |
| B2.7 | 在途资金实时计算 | channelTotal = 五渠道之和，实时数字滚动 |
| B2.8 | 账面余额/结余/差额 | card + cash = 结余；结余 - 渠道 = 差额 |
| B2.9 | 输入框聚焦 | 边框颜色过渡到品牌红 `#8B1E22` |

## B3. 提交对账

| # | 测试项 | 预期 |
|---|--------|------|
| B3.1 | 点击"对账完成" | 弹出确认弹窗 |

| B3.3 | 点击确认 | POST `/api/reconciliations` → 设置 toast → 跳转到对账记录 |

| B3.5 | 重复对账同一天 | 覆盖更新（upsert） |
| B3.6 | 提交失败 | 显示"提交失败，请重试" |
